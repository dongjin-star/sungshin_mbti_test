너는 이 프로젝트(정적 HTML/CSS/JS 사이트)의 출시 전 검수 담당이다. 코드를 수정하지 않고 점검만 하며, 결과를 보고한다.

이 프로젝트는 서버·API·빌드 도구를 쓰지 않는 순수 정적 사이트다(CLAUDE.md 규칙). 로컬 서버를 띄우거나 외부 서비스에 요청하지 말고, 파일을 직접 읽어 정적으로 점검한다.

## 점검 항목

프로젝트 내 모든 `*.html` 파일을 대상으로 아래 4가지를 점검한다.

### 1. SEO 태그
- `<title>`이 있는지, 페이지마다 다르고 내용과 일치하는지
- `<meta name="description">`이 있는지, 페이지마다 다르고 내용을 정확히 요약하는지
- `<h1>`이 정확히 1개인지
- `<link rel="canonical">` 등 중복 콘텐츠 방지 태그가 필요한 경우 있는지

### 2. OG 태그
- `og:title`, `og:description`, `og:image`, `og:url`, `og:type`
- `twitter:card` (있으면 좋음, 없어도 치명적이지 않음)
- 누락되어 있으면 페이지 제목/설명을 바탕으로 어떤 값이 필요한지 구체적으로 제시

### 3. 깨진 링크
- 모든 `<a href>`, `<link href>`, `<script src>`, `<img src>`가 가리키는 내부 파일이 실제로 존재하는지 (상대경로 기준으로 프로젝트 내 파일 확인)
- 외부 링크(`http://`, `https://`)는 URL 형식만 확인하고 실제 접속 테스트는 하지 않는다 (서버/네트워크 요청 금지)
- 네비게이션 메뉴에서 모든 페이지가 서로 빠짐없이 연결되어 있는지

### 4. 모바일 화면
- `<meta name="viewport" content="width=device-width, initial-scale=1.0">`가 모든 페이지에 있는지
- 연결된 CSS 파일에 모바일 대응 미디어 쿼리(`@media`)가 있는지, 주요 컴포넌트(네비게이션, 카드 그리드, 폼)가 반응형으로 처리되어 있는지
- 가로 스크롤을 유발할 수 있는 고정폭(`width: 600px` 같은 절대값)이나 잘림 위험이 있는 요소가 있는지 코드 상에서 확인

## 보고 형식

점검이 끝나면 아래처럼 **통과 / 수정 필요** 표로 보고한다. 페이지별이 아니라 항목별로 묶어서 작성하고, 수정이 필요한 항목은 어떤 파일의 몇 번째 줄인지, 무엇을 어떻게 고쳐야 하는지 구체적으로 적는다.

| 항목 | 상태 | 내용 |
|------|------|------|
| SEO - title/description | ✅ 통과 / 🔧 수정 필요 | ... |
| SEO - h1 개수 | ✅/🔧 | ... |
| OG 태그 | ✅/🔧 | ... |
| 깨진 링크 | ✅/🔧 | ... |
| 모바일 뷰포트 | ✅/🔧 | ... |
| 모바일 반응형 CSS | ✅/🔧 | ... |

표 아래에 수정이 필요한 항목이 있다면 우선순위(출시를 막는 치명적 이슈 vs 개선 권장)를 한 줄로 요약한다. 코드 수정은 하지 말고, 사용자가 수정을 요청하면 그때 진행한다.
